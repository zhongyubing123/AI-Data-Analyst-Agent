# 系统实现要点

一次提问的处理顺序固定：先做指代补全，把上一轮的实体替换进去；再路由判断意图；查数类进入生成、校验、执行、重试；画图类先取数再转图表配置；知识类走检索；其余走普通对话。

意图路由优先用关键词规则。命中销量、销售额、排行、占比、转化率这类词判为查数，命中画、柱状、饼图判为画图，命中什么是、什么意思判为知识问答。规则判断不了才调模型做四分类，这样大多数问题省掉一次模型调用。

生成 SQL 时把字段清单放在提示词最前面，内容固定不变。固定前缀能命中大模型的上下文缓存，降低输入成本。字段清单只列五张汇总表的字段，共十五行。

安全检查是七条规则：空语句、多语句、写操作关键字、查看库结构、DESC、只允许 SELECT、SELECT 星号必须带 LIMIT。字段校验再用字段清单核对表和列，拦住跨表借用字段。

失败重试只做一次。把错误原文回传给模型，让它重写，重写结果还要重新校验。再失败就直接报错，不无限重试。

多轮记忆存在 Redis，键名固定，二十四小时过期，保存上一轮的实体名和实体类型。指代补全靠字符串替换，不是语义理解。
